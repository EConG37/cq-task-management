# 月度与周度规划

## 月度规划

读现有主任务、关键结果和实际进展，再与用户聊天确定本月交付、期限和工作量。主任务=持久项目+量化关键结果；子任务=可执行步骤，可包含未来周。主任务写 `main_tasks` 表，不能因为旧字段名 projects/stages 写到闲置战略定位表。已明确授权“新增/调整”的范围可落地，否则出草案。

月底验收按交付指标与凭证核对，不能把子任务勾完率当作 KR 达成率。主任务与子任务的完成选项不同，分别使用 config 的状态映射。

## 周度规划

1. 使用聊天中的当前日期、时区确定周区间；没有可靠时间时读时钟并转换到用户时区。默认本周周一~周日，中途规划不往过去日期塞新任务。
2. 读取主任务、全部相关子任务、分离的绑定和基线。读上周/逾期 Todoist 任务及评论生成复盘；**规划请求本身不授权回写上周**。
3. 结合用户当前精力和关键结果，挑本周可完成的步骤。用户自己的长期节奏从 preferences 读取；当前安排、休息日和可用时间可覆盖它，不自动补造任务，也不预设所有用户都做同样的三类工作。
4. 出「项目进展 + 本周具体任务/日期 + 关键期限 + 待解决问题」。明确哪些是已授权事实回写，哪些是待确认新排期。
5. 确认或已有明确授权后才写相应内容；每条子任务挂在持久项目父任务下，未来步骤继续留在多维表。

## 临时插队与顺延

- “今天只做 X”：依据用户指令为其他任务提出/执行适量顺延，检查后续工作量及硬期限。不要机械把全部任务无上限后推。
- 同一任务没有做完：保留两边稳定 ID，补充进展、剩余工作并更新原任务日期。
- 延到发布窗口之外：保留已绑定原任务和历史，避免为了“只排一周”擅自删除、解绑或重新创建；新建发布仍限制在确认的近期窗口。
- 纯执行细节可写在原任务描述/评论，不必每条另建任务；每天要单独追踪的工作都需要多维表子任务绑定。
