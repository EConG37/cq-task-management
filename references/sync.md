# 多维表 ↔ Todoist 同步协议

## 身份、字段与授权

`mappings.scopes[scope].main_tasks` 记录主任务→{todoist_id, project_id}；`actions` 只记录子任务→Todoist ID。绑定冲突不能靠标题解决。config、mappings 是资源快照，真实操作前读回验证。新增主任务时先在多维表主任务表建记录；需要发布执行任务时再创建获授权的 Todoist 容器（无日期，可使用 isUncompletable），记录路由。

多维表负责结构、名称、验收；Todoist 负责执行日期、优先级、勾选完成/撤销。更改执行字段前比对基线；旧任务有明确稳定 ID、日期和优先级一致时，可按授权回写真正的勾选或撤销，即使缺少基线。首次接管有其他差异时先核对采用哪一边。`publish` 表示发布已经落地，创建任务取决于实际授权。

事实回写、评价回写、新建发布、排期修改是不同范围。当前会话明确指令或已确认方案授予对应一次操作；持续同步须记录 approved_fields、runner、完整 automation_ids。不因为基线文件为空而反复要求确认相同方案。

## 新任务发布与恢复

1. 限定确认的具体子任务和日期窗口（连续至多 7 天）。新建正式子任务先检查原记录与已有 Todoist 项，再在飞书创建或复用子任务；读回原 record ID、标题及主任务关联。没有读回飞书记录时停止创建对应 Todoist 任务。核对 Todoist 父任务真实 projectId、开放/容器状态；查既有子任务绑定与 `state/outbox`。
2. 新任务描述包含 `source_marker(scope, action_id)` 输出的稳定标记。保留既有 `[goal-flow:…]` 格式以便找回旧任务；查标记时覆盖活跃和已完成任务，不只查今日。多个候选或查询不完整则暂停该任务的创建。
3. 准备 outbox 日志，记 run_id、scope、来源记录、目标路由、操作内容和前置快照，状态 prepared。确认前置快照未被其他会话修改后再创建。每个外部步骤前后更新日志。
4. 创建后立即记录返回 ID；读回 Todoist 核验日期、名称、优先级、项目、父任务和标记，日志改为 todoist_verified。多维表回写 publish=true、todoist_id、planned_for；读回后改为 base_verified。
5. 用两边最终快照验证并提交本地映射/基线，最后标 committed。已有绑定直接复用，不再创建。

API 超时/返回不明时日志标 write_unknown：先查返回 ID、标记、活动记录与日志，不盲目重发创建。创建已成功但多维表失败，只补回写和本地状态。批量部分成功逐条保存证据，不能重试整个成功批次。旧日志只供历史核对，不直接重放旧 payload。

## 已有 Todoist 任务补绑

1. 用 `sync_plan.py audit` 检查当前 Todoist 父任务和项目下的开放及近期完成项，纳入未提交日志及已有绑定候选。匹配依据是 Todoist 稳定 ID、飞书 record ID 和来源标记；同标题只作人工核对线索。用户明确只放 Todoist 的临时任务从补绑名单排除。
2. 已有飞书记录时，核对唯一身份、主任务关联和历史，再按授权在原记录补写发布状态与 Todoist ID。若飞书关联确认为空，但发布标记、唯一 Todoist ID、当前项目和父任务均已核实，可先按授权运行 `pull` 和评论回写。单独列出建议关联的主任务，用户确认后再补关联。多个关联、一个 ID 对应多行、标记无法定位或路由变化时，报告候选供核对。
3. 确认是正式项目任务且飞书无对应记录时，按已授权名单补建飞书子任务并绑定原 Todoist ID。先再次按原 ID 检查飞书、两边绑定和未完成日志。准备 outbox，记录稳定 Todoist ID 和目标主任务。创建飞书行时同次写入名称、主任务关联、Todoist ID、发布标记及获准的执行字段；用现场完成状态和真实日期。Todoist 原任务继续保存原 ID 和评论。
4. 读回飞书时确认原 Todoist ID 唯一、关联和执行字段正确；再读原 Todoist 任务，提交双边基线后进入评论回写。写入结果不明时在同一表按原 Todoist ID 查回，未排除前一次仍在生效或存在并发记录时保留待核对。恢复时复用读回到的飞书行。

## 完成事实与评论

按 [daily-review.md](daily-review.md) 读取。已勾选的任务回写完成，有真实 completedAt 时写实际完成时间；撤销完成清 completed_at 并恢复开放步骤状态。日期/优先级按 Todoist 值回写，多维表相对上次基线也有变化时先核对。无法读取当前状态时标待核对。循环任务按每次执行记录。

## 原任务改期

**改期或改内容前先读该任务的评论**（`td comment list id:<id> --all --json --full`）。把用户记录的最新进展和剩余工作带进调整方案。

先读回确认执行事实和评价已进入多维表，再用获授权的具体改动更新 Todoist 原 ID。CLI 改期用 `--due YYYY-MM-DD`，读回 `due.date`。只传变化字段。跨项目移动按单独获授权的结构变更处理，并再次核对父任务。

更新 Todoist 并读回后，回写多维表计划日期/优先级等；两边再次一致才保存新基线。日期晚于 hard_deadline 时停止该改期并给替代方案，不能静默改硬期限。

## 调整已有计划

1. **先认原任务。** 改期、改标题或调整同一项工作的内容，先读相关 Base 子任务、绑定、Todoist 原任务和评论。把原 ID 带入 `reschedule`；脚本产生冲突时核对原记录，禁止以另建飞书记录或改用 publish 兜底。标题匹配仅用于提示，不能代替身份核验。
2. **区分保留、替换、独立新增。** 拆分时能继续使用的原任务保留原 ID；对确实被替代的旧项，列明原 ID、对应新项和撤出方式。仅对用户授权修改的那一组操作；纯规划先给草案。先核对新项路由、日期和硬期限，再开始撤出。只在部分新工作确实独立时新建。
3. **撤出旧项。** 同步旧项评论和事实后，用 `withdraw`。只处理明确被替代的开放任务。Todoist 原任务清除排期及截止日期（当前 td 的 `--no-due`、`--no-deadline`），保留评论和原条目。读回后在飞书标「取消」、清计划执行日期并移除当前计划区，保留绑定和历史。旧项退出日期视图，完成事实维持原样。单独的永久删除请求按明确授权处理。
4. **发布新项。** outbox 记录这组旧 ID、新 Base 记录 ID、替换关系及读回结果。创建新 Base 记录遇到结果不明时，先找已写入的记录，核对不清就暂停创建。每个替代项在 publish 及恢复时的 pull 快照中都带 `replacement_sources`，包括所有相关旧项及其 Todoist 实时快照。只有旧项两边已撤出才执行创建。创建前再次核对旧项哈希、同父任务的开放待办及来源标记；同名旧项命中时，判断是复用、修正绑定、继续撤出，还是获授权的独立工作。逐条完成写入及读回；失败时从 outbox 的已验证步骤继续。已有新项按原 ID 或来源标记找回。
5. **更新飞书当前计划。** 每次改计划先读取完整「任务详情」，检查原计划是否已过时。用 `current_plan` 改写 `[cq-current-plan]` 区块；日期以独立排期字段为准。旧版未标记详情中，只有确认为本次替换范围内且位于详情开头的旧计划原文，才用 `legacy_plan` 精确移除。保留其他文字和评论，遇到混写或不匹配时核对该段。写后读回日期、标题、计划区、历史和旧项状态。报告实际保留、撤出及新增数量，部分成功标明剩余动作。

## lark-cli 适配

使用 `+field-list` 验证真实字段及选项。子任务完成为「完成」，主任务完成为「已完成」，不能共用一份状态映射。命令参数以当前 CLI 帮助为准。

```powershell
lark-cli base +record-list --base-token <config主库> --table-id <子任务表> --format json --limit 200 --as user
lark-cli base +record-batch-update --base-token <config主库> --table-id <子任务表> --json @batch.json --as user
```

`batch.json` 在当前工作目录；payload 为 {"update_records":{"recID":{"字段名":值}}}。读取 json 的 data.fields、data.record_id_list、data.data 是位置矩阵，按位置 zip 并完整翻页。文本使用字符串；select 使用单元素数组；checkbox 使用布尔；关联主任务使用 [{"id":"recID"}]；清空可使用 null；datetime 写入使用 CLI 支持的日期时间格式并核对时区，读取可能为 ms 时间戳。不要直接把归一化字段名或 ISO 完成时间原样交给不支持它的接口。

批量响应成功不证明每条记录/字段落地，必须读回预期记录并比对。字段选项变更属额外 schema 操作，只有有授权时执行；更新选项前读全量，保留原有选项。

## 基线和并发

用 scripts/commit_state.py 将经过 receipt + 双边快照核验的结果保存到映射、基线、评论指纹。脚本用本地排他锁及临时文件替换；同时核对 state 的原始指纹，避免后提交覆盖另一会话的新状态。外部操作前仍需重新读目标并比对 precondition 的 base_hash/target_hash；锁只保护本地提交，不代表外部任务没有并发修改。

任一写入证据不完整、前置快照改变或字段读回不符时不宣称完成，不保存失败评论为已消费，也不推进该任务的后续排期。
