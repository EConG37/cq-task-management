# 主任务与子任务的结构约定

此文档只描述通用字段语义，不保存任何人的 Base token、表/字段/记录 ID、账号、项目列表或历史任务。实际资源从当前用户的 config.json、mappings.json 及现场读取结果获取。新用户先新建自己的普通空白多维表；也可使用自己已有的表或另行核验过的空白模板副本，不能复用作者的资源。

空白 Base 就绪后，按下方结构建立「主任务」和「子任务」两张表。先检查现有表和字段，复用相同用途的资源；缺项才补建。在用户明确要求初始化配置的范围内执行，完成后读取表、字段、关联目标及选项，将现场 ID 写入自己的 config。新建关系字段应在主任务表建立后指向它。不需要预置示例任务、作者项目或测试记录。

## 两层结构

- main_tasks：主任务=持久项目+关键结果。Todoist 对应无日期的项目父任务容器。
- actions：主任务下的分支子任务=每天具体执行的工作。发布后对应带日期的 Todoist 子任务。
- 主任务和子任务绑定分别保存在 mappings.scopes[scope].main_tasks / actions，数量由用户实际项目决定。
- 闲置战略定位、其它资料表及旧 OKR/日历层不作为本 skill 的写入目标。

## 主任务字段

| 归一化用途 | 模板字段名 | 类型/含义 |
|---|---|---|
| title | 任务 | 文本，项目名 |
| acceptance | 具体交付指标 | 文本，数字+日期+可验收交付 |
| status | 状态 | 单选，主任务完成通常为「已完成」 |
| completed_at | 完成时间 | 日期时间，验收完成后写入 |
| hard_deadline | 截止时间 | 硬期限，不因顺延自动改变 |

主任务状态映射与子任务分开：pending→待开始，active→持续跟进，blocked→阻塞，done→已完成，cancelled→取消。以用户副本真实选项为准，不盲目覆盖已有选项。

## 子任务字段

| 归一化用途 | 模板字段名 | 类型/含义 |
|---|---|---|
| title | 任务 | 文本，具体要做的事情 |
| main_task_id | 关联大目标 | 关联主任务；核验真实目标表 |
| status | 状态 | 单选，子任务完成通常为「完成」 |
| priority | 优先级 | p1→P0、p2→P1、p3→P2、p4→P3 |
| completed_at | 实际完成时间 | 日期时间，采用真实完成事实 |
| publish | 发布到 Todoist | 复选框，表示发布已落地，不能当授权 |
| todoist_id | Todoist ID | 文本，当前用户任务的稳定 ID |
| planned_for | 计划执行日期 | 日期，近期具体执行日 |
| details | 任务详情 | 已有文本，追加任务评论原文与解释 |

子任务状态归一化：pending→待开始，active→主线，blocked→阻塞，done→完成，cancelled→取消。其他真实选项按语义保留或映射，不把开放任务猜成完成。

字段 ID 只在用户自己的 config 中保存。复制后的表/字段/关联必须现场读取核验；同名不证明 ID 一样。评价文本字段未验证时，先核验字段类型和可写能力。

## Todoist 路由

先读当前账号身份，再读用户选择的项目及实际父任务。账号 ID、项目 ID、父任务 ID、执行任务 ID 均属于本地用户状态，不进入分发包。跨账号创建新 scope 和空绑定，不迁移他人的任务 ID。

用户日常看「今日」；复盘另读逾期和已完成绑定任务。任务勾完不自动证明主任务 KR 达成，主任务仍需对照交付证据验收。
